# Recall: что лежит на GitHub и что скачивать

Один проект, два назначения файлов: исходники для разработки и готовое приложение для запуска. Инструкции входят в эти же наборы.

**[Репозиторий MantyZOR/Recall](https://github.com/MantyZOR/Recall)** — публичные исходники и инструкции. **[Последняя готовая версия](https://github.com/MantyZOR/Recall/releases/latest)** — приложение для скачивания.

Порядок публикации новой версии: **[Выпуск релиза по командам](releasing.md)**.

| Что | Где хранится | Для чего |
| --- | --- | --- |
| Код, тесты, публичные примеры и документация | Репозиторий GitHub, вкладка Code | Разрабатывать и сохранять историю изменений |
| `Recall-portable-win-x64.zip` | Раздел Releases того же репозитория | Скачать, распаковать и запустить приложение на Windows |
| `README.md` и папка `docs` | Внутри репозитория; инструкция первого запуска также в переносимой сборке | Прочитать порядок запуска и подключения телефона |
| `Recall-source.zip` в папке `out` | Дополнительный локальный снимок исходников | Передать код одним архивом; отдельно загружать его в GitHub не требуется |
| Карточки, история, сертификаты и полные архивы | На твоих устройствах и в личных резервных копиях | Сохранить свои данные; в исходники и чистую сборку не входят |

## Как скачать приложение

Открой Releases, выбери последнюю версию и скачай **Recall-portable-win-x64.zip**. Распакуй архив в отдельную папку и запусти **Recall.exe**. Порядок подключения телефона есть в меню и в файле **START-HERE.txt**.

Ссылки **Source code (zip)** и **Source code (tar.gz)** GitHub создаёт автоматически. Это код для разработки: для обычного запуска выбирай переносимую сборку. [Как устроены GitHub Releases](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases).

Переносимая сборка рассчитана на нового пользователя. Чтобы перенести в неё свои карточки и память, сначала сохрани полный архив `.recall.zip` из настроек текущего приложения, затем импортируй его в запущенную новую копию. Копия кода на GitHub не заменяет личную резервную копию.

## Как продолжать разработку

Основная рабочая папка — папка проекта, в которой редактируются `src`, `server` и `scripts`. Именно её исходники сохраняются в Git. Папки `out/Recall-source` и `out/Recall-portable-win-x64` создаются упаковщиком заново; изменения в них не станут изменениями исходного проекта.

После изменения кода отправляй коммит в репозиторий. Для новой готовой версии пересобери приложение, создай переносимый ZIP и приложи его к новой версии в Releases. Перезаписывать весь репозиторий архивом не нужно.

## Что входит в исходники

`src`, `server`, `scripts`, тесты, `public` с WASM и иконками, `vendor` с исходником FSRS и его лицензией, документация, примеры, настройки сборки и файлы зависимостей.

Личные `data` и `certs`, базы, резервные копии, ключи, токены, `.env`, `node_modules`, инструменты Rust, временные файлы и готовый `dist` исключены через `.gitignore`. Упаковщик дополнительно использует список разрешённых файлов. Готовый `Recall.exe` собирается из исходника меню и не хранится в Git.

Лицензии сторонних библиотек сохраняются в исходниках и готовой сборке. Лицензию собственного кода выбирает владелец проекта.

## Как собрать пакеты

```powershell
npm ci
npm run build
npm run build:launcher
npm run package:source
npm run package:portable
```

- `out/Recall-source.zip` — снимок исходников.
- `out/Recall-portable-win-x64.zip` — готовое приложение для Releases.
- `out/package-report.json` — размеры и состав пакетов.

Сборочные команды создают файлы на компьютере. Публикация кода и выпуск версии выполняются отдельно.

## Почему рабочая папка занимала около гигабайта

При проверке 8 октября 2026 инструменты Rust занимали около 714 МиБ, зависимости разработки — 197 МиБ, готовая веб-часть — 2,6 МиБ. Эти инструменты помогают разрабатывать проект и не отправляются на GitHub.

Снимок исходников занимает около **0,44 МиБ** в ZIP, готовая сборка Windows — около **39 МиБ** в ZIP. Точный размер текущего пакета записан в `out/package-report.json`. [Для готовых файлов GitHub рекомендует Releases](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github).

В переносимую сборку входят Node.js 24.21.0 LTS Windows x64, необходимые зависимости службы, меню, веб-часть и сторонние лицензии. Упаковщик сверяет официальный SHA256 Node.js; контрольные суммы файлов находятся в `RELEASE.json`. На телефон Node.js, Rust и зависимости разработки не скачиваются.

## Совместимость

Готовое меню предназначено для Windows 10/11 x64 с системным Windows PowerShell/.NET Framework. Node.js включён в архив.

На iPhone обучение, офлайн-запуск и синхронизация проверены пользователем. Интерфейс Android проверяется в мобильном Chromium, инструкция подключения есть; установка сертификата и полный цикл на настоящем Android пока требуют проверки.

Служба написана на Node.js. Для готовых пакетов Linux/macOS потребуются отдельные упаковка и запуск; Windows-меню и сетевые скрипты переносимой сборки рассчитаны на Windows.

## Веб-версия без установки

[Открыть Recall](https://mantyzor.github.io/Recall/) · [Прямой обмен](direct-sync.md). Эта страница содержит только приложение; личные данные остаются в браузере. Ветка `gh-pages` содержит готовый статический сайт, ветка `main` — исходники.

После изменения кода обнови страницу командой `npm run publish:web`. Скрипт пересоберёт веб-версию и отправит только `dist-web` в `gh-pages`. Для первого включения выбери в GitHub Settings → Pages: Deploy from a branch → gh-pages → / (root).
